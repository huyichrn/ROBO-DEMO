# STM32F407 CAN 功能与测试说明

当前两块板均使用 **CAN1**，分别烧录为从节点 1 和从节点 2。电脑通过 USB-CAN 分析仪主动发帧，板端接收并在 LCD 显示最近一帧。收到符合条件的 CANopen 风格请求时，板端发送应答或过程数据。已实测电脑能分别读取两个节点的 SDO 对象。

## 节点号如何分配

`NODE_ID` 是编译时常量，取值范围为 1 到 127。第一块板使用源码默认值 `1`，第二块板的固件在 Keil 构建时传入 `NODE_ID=2`。烧录器将对应的 HEX 写入指定开发板，板子运行时直接使用固件中已编译好的节点号。

| 板子 | 固件 | SDO 请求 ID | SDO 应答 ID |
| --- | --- | --- | --- |
| 第一块 | `atk_f407.hex`，节点 1 | `0x601` | `0x581` |
| 第二块 | `atk_f407_node2.hex`，节点 2 | `0x602` | `0x582` |

SDO 请求 ID 由 `0x600 + NODE_ID` 得到，应答 ID 由 `0x580 + NODE_ID` 得到。两块板的接线顺序可以调换。现场可单发一条 `0x602` 读请求，查看哪块板的 LCD 更新为 TX `582`，以确认节点 2。

## CAN 收发和现场显示

| 项目 | 当前行为 |
| --- | --- |
| 总线 | 经典 CAN，500 kbit/s，正常模式。CAN1 使用 PA11 接收、PA12 发送。APB1 为 42 MHz，预分频为 6，位时间为 1 + 10 + 3 TQ，采样点约 78.6%。 |
| 接收 | 硬件过滤器默认放行全部 ID。FIFO0 接收中断将报文放入软件环形队列，主循环取出后计入 RX。可显示标准帧、扩展帧及远程帧。 |
| LCD RX | 显示累计处理的帧数，以及最近一帧的帧格式、ID、DLC 和十六进制数据。远程帧显示 `Remote frame`。 |
| LCD TX | 显示累计成功发送的帧数，以及最近一次发送尝试的 ID、DLC、数据和 `OK` 或 `ERROR`。驱动检查对应邮箱的发送完成结果，发送失败时 TX 成功计数保持原值。 |
| 刷新与日志 | LCD 每约 200 ms 检查并刷新有更新的区域。串口以 115200 波特率输出接收序号、ID 和 DLC。当前测试构建关闭周期心跳。 |

协议分发只处理标准数据帧。普通测试 ID（如 `0x001`、`0x123`）会更新 RX 计数和最近报文。LCD 展示的是最近一帧，连续收到多帧时，屏幕可能直接跳到较新的帧。软件队列长度为 32 槽，实际可缓存 31 帧，队列满时丢弃新到帧，因此持续高频测试应通过收发计数差值核对。

## 接收处理与应答链路

1. **接收并入队。** CAN1 控制器检查帧格式与 CRC，默认放行合法帧的 ID。硬件把报文放入 FIFO0，触发 `CAN1_RX0_IRQHandler`。中断经 HAL 回调读取帧 ID、帧格式、帧类型、DLC 和数据，再写入软件接收队列。
2. **出队并分发。** 主循环调用 `can_recv_msg()`，每取出一帧就将 RX 加 1，并保存一份给 LCD。然后交给 `slave_rx_process()`。该函数只对标准数据帧进一步分发。NMT 和 SYNC 按各自规则处理，SDO 请求 ID 必须等于本站的 `0x600 + NODE_ID`。
3. **解析并生成应答。** `sdo_server_process()` 检查 DLC 为 8 后，读取命令字、低字节在前的对象索引、子索引及数据字段。读请求会取当前对象值并组装应答。写请求会按对象权限处理，成功后生成确认。遇到不支持的请求时生成中止应答。
4. **发送并更新 TX。** 应用通过 `app_can_send()` 调用驱动。驱动由 `HAL_CAN_AddTxMessage()` 将应答提交到发送邮箱，CAN 控制器封装并发送。驱动检查对应邮箱的 `TXOK`，成功才累计 TX。发送失败时 LCD 显示 `ERROR`。邮箱超时时，驱动请求中止该次发送。

例如，电脑发 `0x602`，数据为 `40 01 20 00 00 00 00 00`。两块板都能接收，只有节点 2 会解析为读取 `0x2001:00`。对象值为 0 时，它在 `0x582` 上发送新组装的应答 `43 01 20 00 00 00 00 00`。节点 1 还会接收到这条 `0x582`，因此在总线空闲、只做一次请求时，节点 1 通常 RX 加 2，节点 2 通常 RX 和 TX 各加 1。帧 CRC 由硬件处理，软件显示和解析的是有效载荷。

## 请求与应答条件

| 电脑发送 | 处理条件 | 板端行为 |
| --- | --- | --- |
| SDO 请求 `0x601` | 标准数据帧，DLC 为 8。 | 对支持的读写请求返回 `0x581`，其中包含读结果或写确认。无效对象、子索引或命令会返回 SDO 中止。 |
| NMT `0x000` | 至少 2 字节，第二字节为 `01`（节点 1）或 `00`（广播）。 | 首字节 `01` 进入运行态，`02` 进入停止态，`80` 进入预运行态。NMT 切换本身无回帧。上电默认预运行态。 |
| SYNC `0x080` | 板端处于运行态才发 PDO。 | 回送 `0x181`，DLC 为 8。数据依次为 2 字节 `0x2000`、4 字节 `0x2001`，末尾 2 字节为 0，数值均为小端序。 |

SDO 支持读取两个对象。 `0x2000:00` 为 16 位只读示例值，当前从节点代码初始化为 0。 `0x2001:00` 为 32 位可读写按键计数，按板上的 KEY0 会递增。对 `0x2001:00` 的写请求成功时，`0x581` 数据以 `60 01 20 00` 开头。当前实现覆盖上述 CANopen 风格的测试流程，互操作验证范围为本次电脑与开发板的测试链路。

## USB CAN TOOL 实测与操作

1. 启动分析仪，选择 **通道 1、500 kbit/s、正常工作**，勾选 **打开 CAN 接收**。
2. 选择 **标准帧、数据帧**，帧 ID 填 `00 00 06 01`，数据填 `40 01 20 00 00 00 00 00`，发送总帧数设为 **1**。点击 **发送消息**。测试第二块板时，将帧 ID 改成 `00 00 06 02`，对应应答 ID 为 `0x582`。
3. 电脑应收到 `0x581`，数据以 `43 01 20 00` 开头，后四字节为对象值。实测应答为 `43 01 20 00 00 00 00 00`。板端 LCD 的 RX 显示 `601`、TX 显示 `581`，收发计数各增加 1。

软件列表中，红点所在行是电脑发送记录，绿点所在行是电脑接收记录。每次请求都有一帧应答时，两种颜色约各占一半。联调截图中，向 `0x601` 发 `01 00 00 00 00 00 00 00` 得到绿色的 `0x581`，数据为 `80 00 00 00 00 00 02 06`。其中 `80` 是 SDO 中止标记，末四字节按小端解码为 `0x06020000`。当前固件也用该中止码处理不支持的 SDO 命令。

批量复测可从 **10 帧、100 ms 周期**开始。发送前后记录板端 RX、TX 计数，并统计电脑收到的 `0x581`。读对象请求全部完成时，这三项的增量均应为 10。到目前为止已验证 SDO 读取和无效命令中止应答，NMT、SYNC/PDO 和对象写入属于源码已实现的路径。
